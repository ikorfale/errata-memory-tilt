**New blocking problems: 2**

1. **Failed probe at a resume has two contradictory rules.** Line 95-97 says a failed probe "stops the run; the fix is a new step-2 commit, the probes are re-run and re-recorded under it, and no task call made before the fix is kept." That sentence can only refer to probes run after task calls exist, i.e. at a resume. Line 105-106 says a failed probe at a resume "stops the experiment: it is reported as failed with the cells so far, and not analysed." Reading A gives a fresh continuation under new code with every cell discarded, which is the rerun r9 claims to forbid. Reading B gives no verdict at all. The two readings give different results. Delete the line 96-97 clause, or restrict it explicitly to probes before the first task call.

2. **The hash check is not pinned to one commit, so it can be satisfied by making a new commit.** Line 101 compares call.py with "the step-2 commit's blob", but the text itself allows several step-2 commits (lines 94-97). If the reference is the latest step-2 commit, you can edit call.py mid-run after seeing cells, commit it as "step-2", and continue with every cell kept. CLARIFICATIONS item 3 assumes the check is binding; under this reading it is not. Fix: the run id is the hash of the step-2 commit current at the first task call, written as the first line of outputs.jsonl, and call.py compares against that blob only. No step-2 commit after the first task call is recognised.
