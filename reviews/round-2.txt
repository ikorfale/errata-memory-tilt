**New blocking problems**

1. **PLACEBO has no role in any decision rule** (`PREREG-draft.md:49-50`). It is defined but appears in neither primary nor secondary. If PLACEBO minus CLEAN shows the same shift as MEM minus CLEAN, nothing says what happens, so after seeing outcomes you can choose to report MEM versus CLEAN or MEM versus PLACEBO as "the" contrast. Fix: keep the primary as MEM minus CLEAN and pre-state that a PLACEBO minus CLEAN median of at least 10 in the predicted direction voids the tilt claim, or make the primary MEM minus PLACEBO. Also say what is length-matched (per task, to that task's MEM prompt) and name the exact stdlib text and offset.

2. **Invalid-answer drop rule is written for two arms but there are four** (`PREREG-draft.md:44-45`). "Dropped in both arms" has two readings: drop the task from every analysis if any arm fails, or drop it only from comparisons that use the failed arm. A SINGLE or PLACEBO failure then changes the primary n under one reading and not the other. Pick one. Also define the parser: an answer with two or more numbers is neither "no number" nor valid under the current text. Say "first integer 0-100 on the first line, else invalid".

3. **SINGLE note selection is ambiguous** (`PREREG-draft.md:47-49`). "The index line mentioning the counterparty handle" assumes one match; "first" is stated only for the keyword fallback. And it is unclear whether the arm gets the index line itself or the note file it points to. Two readings give different SINGLE content and so a different secondary result. Fix: "the note file pointed to by the first index line, in file order, that ...", and commit the selection script with candidates.py.

4. **Wilcoxon zero handling unstated** (`PREREG-draft.md:16`). With round-number answers, d = 0 ties will occur. Dropping zeros versus Pratt's method gives different p-values, and the choice can be made after seeing the data. State the implementation and zero method, and state that the median of signed d is over all tasks including zeros.
