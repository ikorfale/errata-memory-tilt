**New blocking problems: 2** (both in the "Runs and reruns" paragraph, lines 96-104; they are two faces of the same gate).

**B1. Author-controllable aborts license a fresh run after outcomes are visible.** The only licence for a new run is an error-log entry in the previous run. Four of the six entries can be produced at will mid-run: Ctrl-C (logged as "interrupted" by the next start), touching call.py, creating ~/.claude/CLAUDE.md, dropping a file into the project memory folder. outputs.jsonl is appended call by call, so partial medians are visible. Sequence: start, watch, abort when unfavourable, commit any one-line reason in RUNS.md, start again, repeat until a run is allowed to finish. Printing every run's median discloses this but does not remove the choice. Fix: after the first task call there is exactly one run id for the experiment. Every abort pauses it. A restart resumes the same run id and keeps every cell already in outputs.jsonl (each cell is an independent call made under passing checks and the committed call.py hash). No cell is ever discarded after the first task call except by the parse and transport drop rules. Clarification 3's "discards every task output" then becomes "a cell made under a call.py hash other than the step-2 commit's cannot exist, since the hash check precedes the call".

**B2. An interrupted run that is never followed by a start has an empty error log and is, by the text, "the analysed run".** Interruption is written "by the next start" (line 101). Kill the run at a favourable point, never start again, and lines 102-103 make it the analysed run with however many cells it has. "160 task-arm cells" (line 105) is a description, not a condition. Fix: analysis runs only when all 40 tasks are resolved, each task either valid in all four arms or dropped by the parse or transport rule; call.py refuses to produce the report otherwise.
